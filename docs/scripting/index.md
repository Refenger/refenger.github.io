# Скрипты

Скрипты на Lua добавляют песне или типу нот то, чего нет в редакторах. Они работают в **песочнице**: скрипту доступны только базовые функции Lua и модуль LÖVE, а не внутренности игры. Этот раздел — полный справочник: если чего-то здесь нет, у скрипта этого тоже нет.

- [Колбэки](callbacks.md) — когда игра вызывает скрипт и что передаёт.
- [Доступные функции](api.md) — что можно использовать внутри скрипта.

## Где лежат скрипты

```
songs/<Песня>/scripts/
├── main.lua          ← запускается всегда, единственная точка входа
└── utils/
    └── counter.lua   ← подгружается из main.lua через require("utils.counter")
```

- Игра запускает только `main.lua`. Остальные файлы папки выполняются, только если их загрузить через `require`.
- Скрипт запускается заново при каждом входе в песню: переменные с прошлой игры не сохраняются.
- Каждый скрипт работает в своём окружении. Глобальная переменная, объявленная в скрипте, видна только скриптам этой же песни (`main.lua` и его модулям) и не попадает в игру.

### Скрипты типов нот

У каждого типа нот может быть свой скрипт:

```
assets/notetypes/<Тип нот>/
├── image.png
├── image.xml          ← необязательно
├── data.json
└── scripts/
    └── main.lua       ← создаётся кнопкой «Открыть скрипт» в редакторе типов нот
```

- Нота в чарте относится к типу, если её поле `type` совпадает с именем папки типа. В редакторе чартов тип выставляется в панели ноты: «< Тип: … >».
- Скрипт типа загружается, только если в чарте песни есть хотя бы одна нота этого типа. Один скрипт обслуживает все ноты своего типа.
- Скрипт типа работает так же, как скрипт песни: то же [окружение](api.md), `require` видит только папку `scripts` своего типа, и он получает все те же [колбэки](callbacks.md).
- Различие одно: колбэки нот ([`onNoteSpawn`](callbacks.md#onnotespawnnote), [`onNoteHit`](callbacks.md#onnotehitnote), [`onNoteMiss`](callbacks.md#onnotemissnote)) скрипт типа получает только для нот своего типа, а скрипт песни — для всех нот.
- У скриптов песни и типов разные окружения: глобальные переменные одного не видны в другом.

## require

`require(имя)` загружает другой скрипт из папки `scripts` этой песни.

```lua
local counter = require("utils.counter")   -- scripts/utils/counter.lua
local moves   = require("moves")           -- scripts/moves.lua
```

- Точка в имени означает папку, расширение `.lua` можно не писать.
- Модуль выполняется один раз. Повторный `require` возвращает тот же результат, что и в первый раз (то, что вернул модуль, или `true`, если он ничего не вернул).
- Модуль работает в том же окружении, что и `main.lua`: у них общие глобальные переменные.
- За пределы папки `scripts` выйти нельзя. `require("../x")`, абсолютные пути и пути с `:` дают ошибку, как и несуществующий файл и модуль, который загружает сам себя по кругу.
- Ошибку `require` можно перехватить: `local ok, mod = pcall(require, "optional")`.

## Ошибки

Ошибка в скрипте не роняет игру:
- если `main.lua` упал при загрузке (синтаксис или ошибка на верхнем уровне), скрипт не подключается, и песня идёт без него;
- если упал колбэк, текущий вызов пропускается, а при следующем вызове колбэк выполняется снова.

В обоих случаях сообщение с файлом и строкой печатается в консоль:

```
[Script] update: songs/Obsoliit/scripts/main.lua:21: attempt to perform arithmetic on a nil value
```

## Пример

`scripts/utils/counter.lua`:

```lua
local counter = {}

function counter.new(name)
    return {name = name, value = 0}
end

function counter.add(c, n)
    c.value = c.value + (n or 1)
    return c.value
end

return counter
```

`scripts/main.lua`:

```lua
local counter = require("utils.counter")

local script = {}
local beats = counter.new("beats")

function script.createPost()
    print("Песня началась, LÖVE " .. string.format("%d.%d", love.getVersion()))
end

function script.onStep(step)
    if step % 4 == 0 then
        counter.add(beats)
    end
end

function script.keypressed(key)
    if key == "space" then
        print("Битов прошло: " .. beats.value)
    end
end

return script
```
